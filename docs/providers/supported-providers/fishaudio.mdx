## Overview

Fish Audio is a specialized **audio provider** for text-to-speech. Unlike most TTS providers, Fish synthesizes over a **WebSocket** (`/v1/tts/live`) that exchanges **MessagePack-encoded** events. Bifrost fully encapsulates this protocol inside the provider, so Fish Audio is consumed through the standard Speech / SpeechStream interface like any other TTS provider. Conversions include:

- **Model header mapping** - The Bifrost `model` becomes the Fish `model` header (`s1` or `s2-pro`)
- **Voice configuration** - The Bifrost `voice` becomes Fish's `reference_id` (voice model ID)
- **Response format handling** - `mp3`, `pcm`, `wav`, `opus` (defaults to `mp3`)
- **Synthesis parameters** - `temperature`, `top_p`, `normalize`, `sample_rate`, `chunk_length`, `mp3_bitrate`, `latency`, and prosody (`speed`, `volume`)
- **Streaming audio frames** - Server audio frames are emitted as audio deltas; one-shot Speech accumulates them

### Supported Operations

| Operation | Non-Streaming | Streaming | Endpoint |
|-----------|---------------|-----------|----------|
| Speech (TTS) | ✅ | ✅ | `wss://api.fish.audio/v1/tts/live` |
| Realtime (TTS) | - | ✅ | `wss://api.fish.audio/v1/tts/live` (via Bifrost `/v1/realtime`) |
| List Models | ✅ | - | `GET /model` |
| Transcriptions (STT) | ❌ | ❌ | - |
| Chat Completions | ❌ | ❌ | - |
| Responses API | ❌ | ❌ | - |
| Text Completions | ❌ | ❌ | - |
| Embeddings | ❌ | ❌ | - |
| Image Generation | ❌ | ❌ | - |

<Note>
**Unsupported Operations** (❌): Chat Completions, Responses API, Text Completions, Embeddings, Transcriptions, and Image Generation are not supported by Fish Audio (TTS-focused provider). These return `UnsupportedOperationError`.

Both non-streaming `Speech` and streaming `SpeechStream` drive the same `/v1/tts/live` WebSocket. The non-streaming path drives the socket to completion and concatenates the audio frames.
</Note>

### Registering TTS models

When a virtual key has `allowed_models: ["*"]` for `fishaudio`, it allows the models listed in the Fish Audio provider key's `models`. Adding a model to that list registers it in Bifrost. Key updates apply immediately, without a restart.

If the provider key's `models` is `["*"]`, the allowed set falls back to the datasheet's derived `fishaudio/*` rows: `s1`, `s2-pro`, and `s2.1-pro` (see [Pricing](#pricing)). `"*"` cannot be combined with other entries in `models`. To register a model that is not in the datasheet, switch the provider key to an explicit list:

```json
{
  "name": "fishaudio-key-1",
  "value": "env.FISH_AUDIO_API_KEY",
  "models": ["s1", "s2-pro", "s2.1-pro", "<new-model>"],
  "weight": 1.0
}
```

A model that is neither registered nor derived from the datasheet is rejected with `model_blocked`. A governance pricing override works even without a datasheet row, so register a pricing override to price the new model.

Roll out each new Fish Audio model in this order in each environment:

1. In Bifrost, add the model to the Fish Audio provider key's `models` and register its pricing override.
2. Then switch the TTS service (gofish) to the new model using `FISH_SPEECH_MODEL_VARIANT`.

Switching gofish first causes TTS to fail with `model_blocked` if the model is not registered, or records no cost if the model has no pricing.

## Pricing

Fish Audio speech cost is `input_cost_per_character` × billable UTF-8 bytes, reported as `input_chars`.
At every datasheet sync, Bifrost derives each `fishaudio/<model>` catalog row from the corresponding `openrouter/fish-audio/<model>` row.
The derived models are `s1`, `s2-pro`, and `s2.1-pro`.
As of 2026-09, the price is USD 15 per 1M UTF-8 bytes, tracking OpenRouter's resale price, which matches Fish Audio's list price.
A governance pricing override still takes precedence when configured.
If upstream adds a native `fishaudio/<model>` row, it takes precedence over the derived row.

# 1. Speech (Text-to-Speech)

## Request Parameters

### Core Parameters

| Parameter | Mapping | Notes |
|-----------|---------|-------|
| `input.input` | `TextEvent.text` | The text to convert to speech (required) |
| `model` | `model` header | Model variant: `s1` or `s2-pro` (default `s2-pro`) |
| `voice` | `request.reference_id` | Fish voice model ID |
| `response_format` | `request.format` | `mp3`, `pcm`, `wav`, `opus` (default `mp3`) |
| `speed` | `request.prosody.speed` | 0.5–2.0 |

### Advanced Parameters

#### Advanced TTS Parameters

| Parameter | Type | Description |
|-----------|------|-------------|
| `temperature` | float | Expressiveness (0–1) |
| `top_p` | float | Nucleus sampling diversity (0–1) |
| `normalize` | boolean | Text normalization for English/Chinese |
| `sample_rate` | integer | Output sample rate in Hz |
| `chunk_length` | integer | Text segment size (100–300) |
| `mp3_bitrate` | integer | MP3 bitrate in kbps (64, 128, 192) |
| `latency` | string | Trade-off mode: `low`, `normal`, `balanced` |
| `volume` | float | Prosody volume in dB (-20 to 20) |

### Response Format

| Format | Output | Notes |
|--------|--------|-------|
| `mp3` | MP3 | Default; bitrate via `mp3_bitrate` |
| `opus` | Opus | |
| `wav` | WAV | |
| `pcm` | Raw PCM | |

<Note>
Defaults to MP3 if not specified. Unknown formats fall back to MP3.
</Note>

## Response Conversion

Non-streaming `Speech` returns the concatenated audio bytes:

```json
{
  "audio": "<binary audio data>"
}
```

## Streaming

Fish Audio uses a **MessagePack WebSocket** protocol. Bifrost sends `start` (config) + `text` + `stop` and relays each server `audio` frame as an audio delta until the server sends `finish(stop)`:

```json
{
  "type": "audio.delta",
  "audio": "<binary audio chunk>"
}
```

Final chunk:
```json
{
  "type": "audio.done"
}
```

## Authentication

**Bearer token + model header** (sent on the WebSocket handshake):

```
Authorization: Bearer <FISH_AUDIO_API_KEY>
model: s2-pro
```

## Configuration

**HTTP / WebSocket Settings:**
- **Base URL**: `https://api.fish.audio` (default); the WebSocket URL is derived as `wss://api.fish.audio/v1/tts/live`
- **List Models endpoint**: `GET /model`
- **Default model variant**: `s2-pro`

---

## Caveats

<Accordion title="MessagePack WebSocket protocol">
**Severity**: Low
**Behavior**: Synthesis runs over a msgpack WebSocket, not HTTP. The protocol is fully encapsulated in the provider; callers use the standard Speech / SpeechStream interface.
**Impact**: None for callers — Fish behaves like any other TTS provider.
**Code**: `fishaudio/utils.go` (`runSynthesis`, `dial`)
</Accordion>

<Accordion title="Model header vs voice">
**Severity**: Medium
**Behavior**: The Bifrost `model` maps to Fish's `model` header (`s1`/`s2-pro`), while the Bifrost `voice` maps to Fish's `reference_id` (voice model ID).
**Impact**: Set both `model` and `voice` for predictable output. `model` defaults to `s2-pro` if omitted.
**Code**: `fishaudio/fishaudio.go` (`resolveModel`), `fishaudio/speech.go` (`ToFishAudioSpeechRequest`)
</Accordion>

<Accordion title="Rate limits surface as RESOURCE_EXHAUSTED">
**Severity**: Low
**Behavior**: A 429 handshake or a `finish(error)` with a rate-limit message is surfaced with a 429 status.
**Impact**: Downstream maps to `RESOURCE_EXHAUSTED`.
**Code**: `fishaudio/utils.go` (`fishServerError`, `isRateLimitMessage`)
</Accordion>

# 2. List Models

## Request Parameters

By default, with no Fish query parameters (`ExtraParams` empty), ListModels makes exactly one `GET /model?self=true&page_size=1&page_number=1` request per key to validate it. A non-200 response marks the key as failed. The returned voices are ignored; ListModels returns only the models and aliases configured on the provider key, prefixed with `fishaudio/` (`fishaudio/<model>`). A key with `models: ["*"]` and no aliases returns no models. Bifrost also stores this result as the provider's live model list.

Passing any of the Fish query parameters below (forwarded via `ExtraParams`) opts into paginated voice listing. In this mode, `self` defaults to `true` for the **account's own** voices; `self=false` lists the **public** catalog. Use Fish filters to narrow the (very large) catalog:

| Parameter | Type | Description |
|-----------|------|-------------|
| `self` | bool | `true` (default) = your own voices; `false` = public catalog |
| `title` | string | Filter by title/search term |
| `language` | string | Filter by language (e.g. `en`, `ja`) |
| `tag` | string | Filter by tag |
| `sort_by` | string | Sort order (e.g. `score`, `created_at`) |

Pagination is capped at 20 pages (≈2000 models); when a public listing is truncated, a warning is logged suggesting you narrow it with a filter.

```bash
# Own voices
curl "http://localhost:8080/v1/models?provider=fishaudio&self=true"

# Public English voices, searched by title
curl "http://localhost:8080/v1/models?provider=fishaudio&self=false&language=en&title=news"

# Configured models only (key validation)
curl "http://localhost:8080/v1/models?provider=fishaudio"
```

## Response Conversion

For explicit voice listing only, Fish Audio returns voice entries such as:

```json
{
  "total": 1,
  "items": [
    {
      "_id": "802e3bc2b27e49c2995d23ef70e6ac89",
      "title": "My Voice",
      "type": "tts",
      "languages": ["en"]
    }
  ],
  "has_more": false
}
```

In explicit voice listing, each item's `_id` becomes the Bifrost model ID (`fishaudio/<_id>`) and `title` becomes the display name. This mapping does not apply to the default configured-models response.

# 3. Realtime (bidirectional streaming TTS)

Fish's `/v1/tts/live` WebSocket is bidirectional: you stream text chunks in while audio streams back on the same connection. Bifrost exposes this through its standard Realtime API (`/v1/realtime`), so clients speak the **OpenAI-realtime JSON protocol** and Bifrost translates to/from Fish's MessagePack frames.

Fish's wire format is binary MessagePack rather than JSON, so the provider opts into the internal `RealtimeBinaryProvider` capability; the realtime transport frames the upstream leg as binary while the client leg stays JSON. (Existing JSON realtime providers are unaffected.)

### Event mapping

| Client event (OpenAI-realtime JSON) | Fish event | Notes |
|-------------------------------------|------------|-------|
| `session.update` | `StartEvent` | `session.voice` → `reference_id`; `output_audio_format` → `format` (default `pcm`) |
| `conversation.item.create` (input_text) | `TextEvent` | the text to synthesize |
| `response.create` | `FlushEvent` | forces synthesis of buffered text |
| `response.cancel` / disconnect | `CloseEvent` (stop) | ends the session |

| Fish event | Client event (JSON) |
|------------|---------------------|
| `audio` | `response.audio.delta` (`delta` = base64 audio) |
| `finish(stop)` | `response.audio.done` |
| `finish(error)` / `error` | `error` |

### Lifecycle

```
session.update            → StartEvent (once; configures voice/format)
conversation.item.create  → TextEvent   (repeat per text chunk)
response.create           → FlushEvent  (audio streams back as response.audio.delta)
...                       (stream more text + receive audio concurrently)
response.cancel / close   → CloseEvent(stop) → response.audio.done
```

<Note>
**Caveats (v1):**
- The model variant header defaults to `s2-pro` (the realtime interface doesn't surface the requested model to the header layer).
- Fish only emits `finish` at the end of the session, so there's no per-chunk audio boundary — the client receives a continuous `response.audio.delta` stream and a single terminal `response.audio.done`.
- Send `session.update` first; Fish requires `StartEvent` before any text.

For one-shot synthesis, prefer `Speech` / `SpeechStream` (SSE) — Realtime is for interactive, incrementally-fed text (e.g. an LLM token stream).
</Note>
